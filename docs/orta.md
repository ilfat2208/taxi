# ORTA — что это за продукт

> **ORTA — всё рядом.**

ORTA — универсальный суперапп для Казахстана, объединяющий повседневные услуги,
покупки, транспорт и решения для бизнеса в одном приложении. Идея ORTA — единая
цифровая экосистема, где пользователю не нужно устанавливать десятки разных
приложений для бытовых и коммерческих задач.

Этот документ — про продукт: что в него входит, как он выглядит для человека и для
бизнеса, на чём всё держится внутри и с чего начинается запуск. Состояние работ и
планы по первой вертикали — в [`taxi-roadmap.md`](taxi-roadmap.md), технические
решения — в [`adr/`](adr/).

---

## 1. Направления ORTA

| Направление | Что это | Состояние в этом репозитории |
|---|---|---|
| **ORTA Taxi** | Поездки по городу, заказ такси и транспортные услуги. | В работе: профиль водителя и документы, выход на линию, приём геопозиций, живая карта диспетчера. Заказ поездки — Ф2 |
| **ORTA Market** | Маркетплейс товаров, объявления, покупка и продажа между пользователями и компаниями. | Работает и проверено e2e: витрина, корзина, оформление заказа, разделение платежа между продавцами |
| **ORTA Business** | Цифровые инструменты для предпринимателей: заказы, клиенты, сотрудники, услуги, продажи. | Работает частично: кабинет продавца, продажи, расчёты и выплаты на счёт |
| ORTA Cargo | Грузоперевозки, поиск транспорта и исполнителей для доставки грузов. | План (в приложении — «Скоро») |
| ORTA Home | Аренда и продажа недвижимости, поиск квартир, домов, коммерческих помещений. | План |
| ORTA Services | Поиск специалистов и компаний: ремонт, клининг, красота, строительство, бытовые и профессиональные услуги. | План |
| ORTA Build | Строительные материалы, оборудование, спецтехника и услуги для строительства. | План |
| ORTA Delivery | Доставка товаров, документов, посылок и заказов. | План |

Выбор первой вертикали — такси — сделан не по принципу «что проще», а по принципу
«что проверяет платформу на прочность»: только здесь одновременно нужны деньги без
двойных списаний, состояние, которое меняется за секунды (машина, оффер, поездка), и
инфраструктура, которая работает при плохой связи. Всё, что будет проверено на такси,
дальше переиспользуется остальными направлениями без переделки.

## 2. Как это выглядит для пользователя

Вместо отдельных приложений — одно:

```
                          ┌─────────┐
                          │  ORTA   │
                          └────┬────┘
        ┌──────────┬───────────┼───────────┬──────────┐
        │          │           │           │          │
   ┌────▼───┐ ┌────▼───┐  ┌────▼───┐  ┌────▼───┐ ┌────▼────┐
   │  Taxi  │ │ Market │  │  Home  │  │Services│ │ Business│
   └────┬───┘ └────┬───┘  └────┬───┘  └────┬───┘ └────┬────┘
        │          │           │           │          │
   ┌────▼───┐ ┌────▼───┐  ┌────▼───┐  ┌────▼───┐ ┌────▼────┐
   │ Cargo  │ │ Build  │  │Delivery│  │  ...   │ │  ...    │
   └────────┘ └────────┘  └────────┘  └────────┘ └─────────┘
```

Пользователь открывает одно приложение, выбирает направление и получает доступ к
сервису. Никаких «перейдите в другое приложение», никаких отдельных кошельков и
отдельной истории: аккаунт, деньги, заказы и оценки — общие.

Визуальный язык один для всех направлений: главный экран с плитками, нижняя
навигация (Главная, Каталог, Заказы, Профиль), выступающая кнопка «+» для быстрых
действий. Живой экран Android-клиента — `docs/img/orta-home.png`, полный макет
экранов — [`design/orta-screens.html`](design/orta-screens.html).

## 3. Главная идея: свести спрос и предложение

```
Человек:  находит  →  заказывает  →  оплачивает  →  получает услугу
Бизнес:   размещает → получает клиента → принимает заказ → управляет им
```

ORTA ценен не набором экранов, а тем, что обе стороны оказываются в одной
экосистеме: спрос из такси виден водителю, товар из маркетплейса — курьеру, заказ
из Business — в общей истории покупателя. Каждая новая вертикаль добавляет
предложение, не создавая нового приложения.

## 4. Что объединяет все направления

| Общая часть | Зачем нужна всем восьми | Состояние в коде |
|---|---|---|
| **Единый аккаунт** | один вход и одни права на все сервисы | Готово: JWT (HS256 и RS256/JWKS), роли `CUSTOMER`, `DRIVER`, `MERCHANT`, `DISPATCHER`, `SUPPORT`, `ADMIN` |
| **Платежи** | оплата услуги, вывод денег исполнителю, возвраты | Готово: леджжер с двойной записью, резервы (hold → capture/release), идемпотентность на уровне БД, сверка |
| **Карты и гео** | такси, доставка, недвижимость, услуги «рядом» | Частично: Redis GEO для поиска «кто рядом», PostGIS для треков и зон, живая карта диспетчера |
| **Уведомления и события** | заказ принят, машина подъехала, выплата пришла | Готово на уровне фактов: транзакционный outbox → Kafka, дедупликация консьюмеров, DLT. Пуши — план |
| **Рейтинг и репутация** | кому доверять: водителю, продавцу, мастеру | Частично: у водителя есть рейтинг в базисных пунктах, у продавца — история продаж |
| **История и чеки** | «что я заказывал», спорные ситуации | Частично: история платежей с таймлайном переходов, заказы, чеки поездок — Ф2 |
| **Лояльность** | удержание: баллы и программы за общие траты | План |

Практический смысл этой таблицы: новый сервис ORTA не пишет заново ни оплату, ни
геопоиск, ни уведомления. Он описывает свою предметную область и подключается к
платформе — именно так появились `driver-service` и `dispatch-service` рядом с уже
работавшими денежными сервисами.

## 5. Первый этап: один город

```
Шымкент  →  другие города Казахстана  →  региональное масштабирование
```

Запуск начинается с одного города, и это осознанное ограничение, а не осторожность:

* **плотность важнее охвата.** Такси и доставка работают только там, где машин и
  курьеров достаточно, чтобы подача занимала минуты: лучше один город с нормальным
  предложением, чем десять с пустыми картами;
* **один город — одна экономика.** Тарифы, комиссия и подсказки по спросу зависят
  от города; настраивать это сразу для страны значит угадывать;
* **поддержка рядом.** Спорные поездки и выплаты разбираются людьми, и на старте эти
  люди должны знать город;
* **платформа мультигородняя с первого дня.** Город — это данные (тарифы, геозоны,
  сервисы), а не архитектура: расширение не потребует переписывания.

## 6. Что уже работает, а что нет

Работает и проверено на живом стеке:

* **деньги**: счета и переводы по номеру, комиссии, лимиты и антифрод, идемпотентность,
  сверка леджера (инварианты проверяются скриптами);
* **ORTA Market**: витрина → корзина → оформление → заказ `PAID` с платежом на
  каждого продавца;
* **ORTA Business**: регистрация продавца, продажи, расчёт и выплата на его счёт;
* **ORTA Taxi (часть)**: регистрация водителя, документы со сроком действия, выход
  на линию, приём геопозиций, поиск ближайших машин и живая карта диспетчера;
* **клиенты**: web (React) и Android (Kotlin + Compose) с главным экраном ORTA.

Пока нет — и в приложении это помечено «Скоро», а не спрятано:

* заказ поездки: котировка, поиск водителя, поездка, чек такси (Ф2–Ф4 плана);
* Cargo, Home, Services, Build, Delivery: направления не начаты;
* пуши, программы лояльности, кабинет бизнеса за пределами продаж и выплат.

Принцип, которого проект держится: **не показывать функций, которых нет**. Плитка
без реализации ведёт на честный экран «раздел ещё не реализован» с объяснением,
что появится и когда.
