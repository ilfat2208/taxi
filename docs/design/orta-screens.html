Всё рядом

Супер-приложение: такси, маркетплейс, деньги и кабинет водителя — на одной платформе с общим леджжером двойной записи, идемпотентностью на уровне БД, транзакционным outbox и единым контрактом ошибок RFC 7807. Этот борд — дизайн-предложение по экранам клиента: он не спорит с уже работающим приложением и честно помечает то, чего в коде ещё нет.

Общие правила этих состояний

одно для всех экранов
Никогда не показываем «пусто» вместо «не загрузилось»

Пустой ответ (200, items: []) и ошибка запроса — разные экраны. Смешать их значит соврать пользователю.

5xx всегда с correlationId

Один и тот же id идёт по HTTP, MDC, Kafka-заголовку и логам сервисов — поддержке достаточно одной строки от пользователя.

Тексты — из code, а не из detail

Клиент выбирает фразу по машинному коду, а detail показывает как есть: он для человека, но не для логики.
